# サーバ証明書 失効申請TSV（5-3-3）

種別ID: `server-revoke` / 全13列 / 1ファイル最大99件

**この申請は、証明書が不要になった・秘密鍵が漏洩したなど、利用管理者が能動的に失効を行う場合のためのもの。更新（server-renew）に伴う旧証明書の失効TSVはUPKIシステム側で自動生成されるため、このスキルで作成する必要はない。** 「更新したので旧証明書の失効TSVを作りたい」という依頼には、作成不要であり置き換え完了を登録担当者へ通知すればよい旨を案内する。

ACME移行後に移行前の証明書を失効する場合はこの申請を使うが、**失効は必須ではなく、切り戻しに備えて有効期間満了まで残してもよい**（acme-create.md参照）。

| # | 項目名 | 必須 | 文字 | 最大 | 内容 |
|---|---|---|---|---|---|
| 1 | 主体者DN | ○ | 半角英数記号 | 250 | 失効対象証明書のDN（"CN,O,L,ST,C" の順）。不一致はエラー |
| 2–3 | （空欄） | | | | |
| 4 | 失効対象証明書シリアル番号 | ○ | 半角数字 | 50 | 10進数または16進数（`0x`プレフィクス） |
| 5 | 失効理由 | ○ | 半角数字 | 1 | 下表参照 |
| 6 | 失効理由コメント | △ | 全角・半角 | 128 | 必要な場合のみ |
| 7–9 | （空欄） | | | | |
| 10 | 利用管理者mail | △ | 半角英数 | 78 | **利用管理者が変更になった場合のみ**、変更後のアドレス |
| 11–13 | （空欄） | | | | |

## 失効理由コード

| コード | 意味 | 使う場面 |
|---|---|---|
| 0 | unspecified（未定義） | 他に該当がない場合 |
| 1 | KeyCompromise（鍵の危殆化） | **秘密鍵が第三者に漏洩した・恐れがある場合のみ。それ以外で絶対に選択しない** |
| 3 | affiliationChanged（主体DNの変更） | 組織名変更など |
| 4 | superseded（証明書の更新・記載内容の変更） | **更新に伴う旧証明書の失効は通常これ** |
| 5 | cessationOfOperation | FQDN利用停止・ウェブサイト閉鎖に伴う利用終了 |

## 聞き取り時の注意

- 失効理由を聞くときは、まず「なぜ失効するのか」を自由回答で聞き、こちらでコードに当てはめて確認するほうが安全（初心者に「危殆化」を選択肢として見せると誤選択しやすい）。
- ユーザーがコード1を希望した場合、「秘密鍵が外部に漏れた、または漏れた可能性がある事案ですか？」と必ず確認する。違うなら適切なコードを提案する。
- シリアル番号は発行時の通知メールや、`openssl x509 -in server.crt -noout -serial`、ブラウザの証明書詳細で確認できると案内する。
