# ACME利用情報 作成申請TSV（5-5-1）

種別ID: `acme-create` / 全13列 / 1ファイル最大99件

ACME利用を開始する（ACMEアカウントを払い出してもらう）ための申請。**CSRは不要**（証明書発行時にACMEクライアントが自動処理する）。

| 2 | 証明書プロファイルID | ○ | 半角数字 | 1 | `3`: サーバ証明書（sha256WithRSAEncryption）/ `11`: サーバ証明書（ecdsa-with-SHA384） |
| 3–7 | （空欄） | | | | |
| 8 | 利用管理者氏名 | △ | 全角・半角 | 64 | |
| 9 | 利用管理者所属 | △ | 全角・半角 | 64 | |
| 10 | 利用管理者mail | ○ | 半角英数 | 78 | 利用管理者の連絡先として登録する。**EABクレデンシャルはこのアドレスには送信されない**（下記参照） |

## ACME固有のDNルール（サーバ証明書TSVより厳格）

- CN=＜利用管理者FQDN（項目11と同値）＞
- O=＜機関名英語表記＞。登録担当者の所属機関名と一致し、当該機関が登録状態にあること。**Oを合わせた値は128文字以内**
- L=＜届出済み市区町村＞、ST=＜届出済み都道府県＞（両方指定）
- C=JP
- **OU使用不可**
- Email属性を含めない
- 属性名は**大文字のみ**（cn= はエラー）
- 「=」の前後、「,」の後、値の先頭に**スペース不可**
- **既存の同一主体者DNのレコード（従来方式の証明書等）があっても、作成申請はそのまま受理される**（自動更新での事故を防ぐための仕様。事前の失効は不要）

## 聞き取り時の補足

- **EABクレデンシャル（KID・HMACキー）はメールで送付されない。** 従来方式の証明書取得URL通知とは異なり、登録担当者がTSVを証明書自動発行支援システムに登録した際に画面上に表示される。登録担当者から利用管理者へ、機関で定めた安全な方法で受け渡す運用になる。利用管理者から「EABがメールで届かない」と相談された場合は、登録担当者に確認するよう案内する。
- フォーマットエラーの詳細FAQ: https://nii-auth.atlassian.net/wiki/spaces/UPKIFAQ/pages/43745716
- 既に同じFQDNで従来方式の証明書を使っている場合でも、事前の失効なしで作成申請できる。**旧証明書の失効は必須ではない**: 新証明書への置き換えと動作確認の完了後、失効したい場合のみ失効TSV（server-revoke、理由4）を作成する。切り戻しに備えて旧証明書を残し、**有効期間満了を待っても問題ない**ことを案内する。
- マルチドメイン（dNSName）を使う予定は最初に確認する。あとからの追加は acme-renew になる。
- **項目12は利用予定のACMEクライアント名ではなく、証明書を実際にインストールして使うサーバソフトウェア（apache, nginx, Tomcat, OpenLDAP 等）を書く。** ACME申請ということでcertbot/legoを書きたくなりやすいので、聞き取り時に取り違えないよう確認する。
